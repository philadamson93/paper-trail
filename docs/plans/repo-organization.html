Plan — agent-instruction-forward repo organization

Status: Implemented + behaviorally smoked (mechanical move + path migration + control_flow.md + brevity audit landed 2026-06-09; behavioral smoke 2026-06-24; grounding loop environment-blocked, not merge-blocking) Branch: repo-organization (off feature/paperclip-primary-workflow) Source: repo-organization.md SHA: 358a75b726ca Generated: 2026-06-24
TL;DR Make paper-trail's ship surface visible on GitHub by introducing a top-level src/ directory that mirrors today's .claude/. Subdirectory symlinks keep Claude Code's discovery working; shipped runtime references migrate to src/ (RD-2); directory-shaped skills like paperclip/SKILL.md ship as part of the mirrored surface (RD-3). Author mode is redesigned to take a manuscript path argument (RD-9, supersedes RD-1) — no cross-repo vendoring; paper-trail lives at one canonical path and the slash command resolves its own references regardless of the user's cwd. The flagship deliverable is src/specs/control_flow.md tracing the orchestrator-to-dispatch-to-subagent-to-validator graph. The plan is now implemented on the repo-organization branch: the mechanical move, RD-2 path migration, control_flow.md, and the light brevity audit all landed 2026-06-09; a Codex implementation audit + post-review fixes followed; and headless behavioral smokes ran 2026-06-24. See Review history for the 3 reviewer passes + RD-9 architectural pivot, and Implementation & smoke results for what actually ran.

RD-9 — Author mode takes a manuscript path argument (supersedes RD-1)

Decision: paper-trail lives at one canonical path (the user's clone). The user runs Claude Code with paper-trail's directory available — three patterns, any one works:

Design pins

Concrete shape decisions inside the Implementation surface. Each is load-bearing for the diagrams above — moving any pin reshapes the blast radius.

Subdirectory-level symlinks, not file-level📌 PIN

One symlink per content-bearing subdirectory (.claude/commands/ → src/commands/), not one per file. Avoids the brittleness of per-file symlinks and keeps the directory listing legible if a fresh agent looks under .claude/ directly.

src/ is fully gitignore-clean and tracked📌 PIN

No build step, no generated files — what's checked in IS the ship surface. The symlinks are tracked too (git stores them as symlinks, recreates on clone).

No top-level templates/ after the move📌 PIN

Moves to src/templates/. Reduces top-level directory count and groups templates with the rest of the ship surface. CLAUDE.md update reflects this.

CLAUDE.md and docs/journal/ stay top-level📌 PIN

They are dev-and-product-docs scaffolding, not ship surface. The docs/ directory is correctly named for human-facing documentation.

No back-compat for old .claude/-direct path references📌 PIN

Per memory feedback_rework_for_quality.md, refactor cleanly. Plan-doc references update in lockstep with the move. src/ is canonical; .claude/ is publication. If symlinks ever break, regenerate from src/; never edit through .claude/.

Recognized non-shipped top-level directories post-move📌 PIN
  • docs/ — human-facing documentation
  • examples/ — canonical fixture runs
  • experiments/ — gitignored scratch (sarol-leftovers and probe artifacts)
  • dev/ — engineering tooling for validating the ship surface (see docs/plans/run-isolation-framework.md)

The naming choice dev/ rather than tools/ reflects that "paper-trail" itself is the tool; calling something else tools/ would be confusing for a repo-browser. dev/ reads as "engineer ergonomics, not the product."

Decision policy: instructions vs code

Meta-principle for future feature plans, captured here so the heuristic is visible. plan-check adds a rationale-required check on plans that introduce code.

  1. First consider: can this be a slash command, a dispatch prompt slot, a skill, or a spec field? (Markdown-first default.)
  2. Fallback: Python helper in src/scripts/. Only when:
    • The work is genuinely non-Markdown — file parsing (GROBID), HTML rendering, JSON validation
    • Or the work is a determinism guarantee — same input must produce identical output (validators, schema checks)
    • Or the work is performance-bound — searching across many local files, batch operations
  3. Never: write Python plumbing that wraps a Markdown task. If a feature can be specified as a prompt edit, it should be.

Migration-manifest regex must be POSIX ERE (no PCRE lookaheads; no \b word boundary)⚠️ WATCH

Three regex variants for the manifest have been tried and broken — the third only caught by the Codex second pass:

  • '\.claude/|^\s*templates/' — ^\s* anchor matches zero templates/ hits (none of the references begin with leading whitespace).
  • 'templates/(?!claims_ledger\.md$)' — PCRE negative-lookahead. git grep -E is POSIX ERE; rejects with fatal: repetition-operator operand invalid. Semantically wrong too: templates/claims_ledger.md IS being moved.
  • '\.claude/|(\b|/)templates/' — looks correct, isn't. git grep -E treats \b as the literal character b, not a word boundary. Returns 12 hits instead of the correct 45 and misses every sentinel doc. A count-only sanity check passes coincidentally.

Use instead: git grep -nE '\.claude/|(^|[^[:alnum:]_])templates/' -- ':!docs/journal/*' ':!docs/plans/reviews/*'. POSIX-character-class negation handles the boundary correctly. Sanity-check by both count AND sentinel files. (2026-06-09 the correct regex returned 306 hits / 48 templates/ hits with all five sentinels — confirming the boundary fix.)
