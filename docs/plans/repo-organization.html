Resolved decisions

Three design forks the 2026-05-18 Codex review surfaced; resolved the same day. Each pin is load-bearing for the diagrams above.

RD-1 — Author-mode vendoring

Decision: vendor-copy src/ alongside .claude/. Author-mode workflow stays supported; README's "Install into a writing repo" section gets a one-line update from "copy .claude/ and templates/" to "copy src/, .claude/, and templates/ (in that order — .claude/ contains symlinks that must resolve against the vendored src/)." After templates/ moves under src/templates/, the instruction collapses back to two: src/ and .claude/.

Mandatory smoke test (gates the reorg): create a clean temp dir, vendor per the new README instruction, verify .claude/commands/paper-trail.md resolves through the symlink, open the dir in Claude Code, invoke /paper-trail --author <tex-fixture>, confirm completion without errors.

RD-2 — Path policy

Decision: migrate every shipped runtime reference to src/.... .claude/ is publication-only — never edit through it, never reference it from a shipped prompt/spec. Symlinks keep execution working; the migration buys single source of truth.

Enforcement: repo-wide grep sweep (git grep -nE '\.claude/' -- 'src/' 'README.md' 'docs/' ':!docs/journal/*' ':!docs/plans/reviews/*') must return empty or every hit has an inline annotation explaining why it stays as .claude/.

RD-3 — Directory-shaped skills

Decision: nested skills like paperclip/SKILL.md are part of the mirrored ship surface. Move spec is directory-aware: an entry under .claude/skills/ is either a single <name>.md or a directory of shape <name>/SKILL.md. Discovery smoke test must explicitly load one of each shape.

Why it matters: the feature-paperclip-first-architecture.md workflow depends on the paperclip skill. A move spec using only *.md globs would silently leave paperclip/ at the old location and break that workflow on day one.

Design pins

Concrete shape decisions inside the Implementation surface. Each is load-bearing for the diagrams above — moving any pin reshapes the blast radius.

Subdirectory-level symlinks, not file-level📌 PIN

One symlink per content-bearing subdirectory (.claude/commands/ → src/commands/), not one per file. Avoids the brittleness of per-file symlinks and keeps the directory listing legible if a fresh agent looks under .claude/ directly.

src/ is fully gitignore-clean and tracked📌 PIN

No build step, no generated files — what's checked in IS the ship surface. The symlinks are tracked too (git stores them as symlinks, recreates on clone).

No top-level templates/ after the move📌 PIN

Moves to src/templates/. Reduces top-level directory count and groups templates with the rest of the ship surface. CLAUDE.md update reflects this.

CLAUDE.md and docs/journal/ stay top-level📌 PIN

They are dev-and-product-docs scaffolding, not ship surface. The docs/ directory is correctly named for human-facing documentation.

No back-compat for old .claude/-direct path references📌 PIN

Per memory feedback_rework_for_quality.md, refactor cleanly. Plan-doc references update in lockstep with the move. src/ is canonical; .claude/ is publication. If symlinks ever break, regenerate from src/; never edit through .claude/.

Recognized non-shipped top-level directories post-move📌 PIN
  • docs/ — human-facing documentation
  • examples/ — canonical fixture runs
  • experiments/ — gitignored scratch (sarol-leftovers and probe artifacts)
  • dev/ — engineering tooling for validating the ship surface (see docs/plans/run-isolation-framework.md)

The naming choice dev/ rather than tools/ reflects that "paper-trail" itself is the tool; calling something else tools/ would be confusing for a repo-browser. dev/ reads as "engineer ergonomics, not the product."

Decision policy: instructions vs code

Meta-principle for future feature plans, captured here so the heuristic is visible. plan-check adds a rationale-required check on plans that introduce code.

  1. First consider: can this be a slash command, a dispatch prompt slot, a skill, or a spec field? (Markdown-first default.)
  2. Fallback: Python helper in src/scripts/. Only when:
    • The work is genuinely non-Markdown — file parsing (GROBID), HTML rendering, JSON validation
    • Or the work is a determinism guarantee — same input must produce identical output (validators, schema checks)
    • Or the work is performance-bound — searching across many local files, batch operations
  3. Never: write Python plumbing that wraps a Markdown task. If a feature can be specified as a prompt edit, it should be.

Implementation steps

Step 1 — Build migration manifest⏳ PENDING

The canonical migration manifest is generated, not hand-curated. Run from the repo root:

git grep -nE '\.claude/|^\s*templates/' -- ':!docs/journal/*' ':!docs/plans/reviews/*'

Every hit is a candidate for path migration per RD-2. Classify each before editing:

  • (a) Shipped runtime artifact (prompt / spec / command) → migrate to src/...
  • (b) Doc or plan prose → migrate to src/...
  • (c) .gitignore rule → update carveout pattern
  • (d) Intentional reference to publication-target .claude/ (rare; annotate inline)

Verify gate: manifest is reviewed before any git mv runs.

Step 2 — git mv shipped artifacts to src/⏳ PENDING

Preserve git history with git mv. Inventory:

  • .claude/prompts/*.md → src/prompts/*.md
  • .claude/specs/*.md → src/specs/*.md
  • .claude/skills/<entry> → src/skills/<entry> — entry is either single <name>.md or directory <name>/SKILL.md (current entries: doc-split-check.md, plan-check.md, paperclip/SKILL.md) — re-enumerate via ls .claude/skills/ at implementation time
  • .claude/scripts/*.py → src/scripts/*.py

Step 6 — Smoke test suite (the gate)⏳ GATE

Eight required checks before the reorg is considered shipped:

  1. Slash-command discovery — /paper-trail resolves through the symlink.
  2. Per-command coverage — /ground-claim and other commands resolve.
  3. Single-file skill discovery — doc-split-check, plan-check auto-load.
  4. Directory-shaped skill discovery (closes Codex C3) — paperclip auto-loads via trigger or explicit invocation. Single-file discovery passing does not imply directory-shape passing.
  5. Author-mode vendoring smoke — five-step temp-project procedure from "Author-mode packaging" section.
  6. Repo-wide path-policy sweep — git grep -nE '\.claude/' -- 'src/' 'README.md' 'docs/' ':!docs/journal/*' ':!docs/plans/reviews/*' returns empty or annotated only.
  7. Git history continuity — git log --follow works through the move on at least one file per directory.
  8. Clean working tree — git status shows no spurious symlink diffs.

Sync-script fallback gate (OQ1 alternative): only triggers if the discovery checks fail. In that case the fallback (make sync) requires its own follow-up commit updating docs/claude_ops.md's "no build step" assumption.

Step 7 — Light brevity audit⏳ PENDING

Content-driven on the 698-line paper-trail.md; skipped on prompts under 100 lines. Looks for two patterns only:

  1. Reference material that duplicates a spec — collapse a 50-line schema explainer in paper-trail.md to a 1-line pointer to src/specs/verdict_schema.md. The orchestrator agent reads the spec on demand; the schema isn't loaded into context every turn.
  2. Human-orientation-only content — "this phase exists because of the April reversal..." kind of context. Useful for a code reviewer; not load-bearing for the agent. Move to a Provenance section at the bottom or to a journal entry.

Out of scope for this audit: rewriting prompt prose, touching slot lists, deciding whether a {{slot}} is underspecified. Audit deliverable: per-prompt before/after line count + a one-paragraph summary.

Gotchas

Vendoring contract is a cross-repo API surface⚠️ WATCH

The README's "Install into a writing repo" section is effectively a public API. The original symlink plan would have silently broken it (cp -R preserves symlinks; the target dangles unless src/ is copied alongside). RD-1 settled this by vendoring src/ + .claude/ together, but any future symlink layout change must update README + re-run the vendoring smoke in the same commit.

Don't conflate validate_claims.py with exit-schema validation⚠️ WATCH

The original plan's control_flow.md example tables named validate_claims.py::EVIDENCE_SHAPE and similar as the exit validators. There is no such function. validate_claims.py is the pre-dispatch manuscript validator (TEXT_ANCHOR_MISSING / FRONT_MATTER_ANCHOR / CITEKEY_MARKER_MISMATCH). Exit-schema rules live in src/specs/verdict_schema.md §"Validation rules" and are orchestrator-enforced inline. Future edits to control_flow.md must keep these distinct.

Line numbers in control_flow.md drift on every prompt edit⚠️ WATCH

Plan's original draft pinned dispatch sites to specific line numbers (paper-trail.md:396, :430, :507). Two of those were silently wrong (:430 is ledger render, not adjudicator dispatch; :507 is Phase 5 header, not verifier). Fix: anchor on stable section headings, optionally paired with a current line number + a re-pin grep procedure. plan-check gets an enforcement step.

Skills inventory must enumerate directories, not just *.md⚠️ WATCH

The original move spec used *.md globs and silently omitted .claude/skills/paperclip/SKILL.md (the only directory-shaped skill today). Fix: enumerate .claude/skills/<entry> at implementation time, where an entry is either a single *.md or a directory containing SKILL.md. Discovery smoke test must cover both shapes — one passing does not imply the other.

Open questions

OQ1 Sync mechanism fallback if symlinks break Claude Code discovery

Default is subdirectory-level symlinks (the Step 6 smoke gates this). If discovery fails in practice, fall back to (a) gitignore .claude/<dir>/ + make sync step that copies src/<dir>/* into .claude/<dir>/ before sessions, or (b) keep .claude/ as the canonical home and skip the src/ mirror entirely. Fallback (a) requires a follow-up commit updating docs/claude_ops.md's "no build step" assumption. Decision: try symlinks first; back off only if measurable breakage.

OQ2 Per-prompt brevity audit threshold
