TL;DR

Paper-trail's read path becomes paperclip-first by default. A May 1 2026 re-probe of the canonical Adamson fixture measured 27/56 (48%) greppable full-text via paperclip — roughly 4× the April baseline that triggered the 2026-04-18 reversal.

The plan ships paperclip-mode and PDF-mode as parallel dispatch paths under one shared exit schema, with a 1.1 to 1.2 hard schema bump adding source_mode and paperclip_handle. Mixed-path is permanent (paywalled MRM / IEEE TMI references will not deposit to arxiv); the external slice is not a deprecation target.

Plan-only; no code yet. Gated behind repo-organization and run-isolation-framework plans per docs/NEXT.md, and coordinated with the in-flight feature/multi-cite-and-neighbor-claims branch (lands at schema 1.1 first, then paperclip-first rebases and bumps to 1.2).

Phase steps (expand for detail)

Each phase is collapsible — closed by default. Inside: what changes, files touched, verify-gate, and a feedback field.

Phase 0 — input PDF parse unchanged

Extract bibliography from the user's input PDF. pdftotext then heuristic ref parsing then CrossRef cross-check; emit refs.bib and parse_report.md. Paperclip is corpus-side; it does not help parse the user's manuscript.

Plan adds: Phase-0 should also call paperclip config and check the Auth: ✓ line. If unauthed, the run goes straight to --paperclip=off with a one-line warning (per Open Question 4).

Phase 1 — /verify-bib paperclip-aware core change

For each reference, in order:

  1. Try paperclip exact-DOI lookup (PMC, bioRxiv, medRxiv). Hit → coverage: paperclip, store paperclip_handle, record metadata diffs.
  2. Miss → paperclip title-search against arXiv. Filter by normalized-title overlap (≥0.6) and ±2-year sanity. Hit → coverage: paperclip.
  3. Miss → paperclip abstracts source for identity resolution (catching wrong-paper citations). Hit → coverage: external (paperclip cannot ground but can verify).
  4. Fall back to today's CrossRef → arXiv-API → Semantic Scholar chain. Mark coverage: external or unresolved.

Files: .claude/commands/verify-bib.md, .claude/commands/paper-trail.md (around line 200).

Verify gate: Phase-1 summary line on the Adamson fixture should read verified: 56/56 (paperclip:~27, external:~29, unresolved:0) (May 1 probe result, ±2 references).

Phase 2 — /fetch-paper coverage-aware core change

Branch on coverage:

  • paperclip → skip download. The paper never hits disk. Pass through to Phase 3 with paperclip_handle.
  • external → existing download path (paper-search MCP → PapersFlow → CrossRef OA → arXiv API). Save to pdfs/<citekey>.pdf. On paywall, flag for user triage as today.
  • unresolved → skip; flag for user triage at end of run.

Pinned framing: paywalled fallback is not a regression — today's PDF-centric path already requires manual download for paywalled refs. Paperclip-first shrinks the slice, not the failure mode.

Files: .claude/commands/fetch-paper.md, .claude/commands/paper-trail.md (around line 230).

Verify gate: on Adamson with --paperclip=prefer, ~27 refs skip download; ~29 hit existing fetch path.

Phase 2.5 — Ingest (PDF-only) unchanged shape

Only runs over PDFs actually fetched (the external slice). GROBID and figure extraction unchanged. Cache ingest artifacts; skip on re-run.

If GROBID fails (image-based PDF, odd layout), fall back to pdftotext plus tesseract OCR and mark the entry ingest_mode: ocr_fallback. Phase 3 propagates this to the verdict envelope's source_mode as pdf_ocr_fallback (lower confidence weighting in the adjudicator's prompt).

Phase 3 — /ground-claim mode-aware core change

Orchestrator dispatches Pass 1 (extractor) and Pass 2 (adjudicator) per (claim, citekey) pair. The new branch is in extractor selection:

  • source_mode: paperclip → dispatch with extractor-dispatch-paperclip.md. Subagent operates on /papers/<paperclip_handle>/ via paperclip CLI primitives (grep, cat sections, ask-image on figures, optionally map across sibling handles).
  • source_mode: pdf or pdf_ocr_fallback → dispatch with extractor-dispatch-pdf.md (current extractor-dispatch.md, renamed). Existing local-rg / pdfplumber workflow.

Both extractors produce the same evidence-JSON shape. Pass-2 adjudicator is mode-blind: it reads the evidence JSON plus the rubric and emits a verdict, never knowing whether evidence came from paperclip or PDF.

Multi-cite handling (co_cite_context.sibling_citekeys) carries over unchanged from the orchestrator's flat co_citekeys slot; mode does not affect it.

Files: .claude/commands/ground-claim.md (Mode section), .claude/commands/paper-trail.md (around line 315 onward + line-396 dispatch payload JSON + slot placeholders), .claude/prompts/extractor-dispatch-paperclip.md (NEW), .claude/prompts/extractor-dispatch-pdf.md (RENAMED), .claude/specs/verdict_schema.md (1.2 bump).

Verify gate: single claim (e.g., C001) run end-to-end in paperclip mode; evidence JSON validates against schema 1.2.

Phase 3.5 — verifier mode-aware minor

Verifier picks one attestation line and re-checks it. If source_mode: paperclip, re-runs the same paperclip grep against the same handle. If source_mode: pdf*, re-runs existing local re-check. Exit shape is mode-agnostic.

Open Question 3: stay deterministic or add an LLM-based judgment layer? Default: deterministic in v1; LLM-based is a separate plan.

Phase 4 — triage unchanged

Interactive AMBIGUOUS triage. Mode-blind.

Phase 5 — render mode-aware HTML minor

Add source_mode badge per claim row in the HTML renderer. Color-key: paperclip = green, pdf = blue, pdf_ocr_fallback = yellow (lower confidence visual signal).

Files: .claude/scripts/render_html_demo.py, templates/claims_ledger.md.

Gotchas + pinned design decisions

Mixed-path is permanent, not a temporary state

Paperclip and PDF dispatch prompts both ship and stay. Paywalled MRM and IEEE TMI references will not deposit to arxiv; the external slice is not a deprecation target. Two extractor prompts, one shared exit schema, one shared adjudicator.

The abstracts source is a Phase-1 helper, not a Phase-3 source

The PubMed-abstracts corpus paperclip 0.3.0 ships is explicitly "no full text." It can help bib verification and catch wrong-paper citations. Phase 3 never reads from abstracts — a hit there marks coverage: external.

No back-compat for the 1.1 to 1.2 schema bump

Per memory feedback_rework_for_quality.md. Old verdict files without source_mode will fail validation; users re-run paper-trail to regenerate. No migration shim.

Authentication failure is non-fatal

If paperclip config shows unauthenticated, the run proceeds in --paperclip=off with a one-line warning. Product remains useful without paperclip (parity with today's PDF-centric path).

Coordination with feature/multi-cite-and-neighbor-claims

Both branches touch paper-trail.md Phase 3 and the line-396 dispatch payload. Sequence: land Features 1+2 first (additive 1.0 → 1.1) → paperclip-first rebases onto stable per-ref + joint dispatch shape → bumps schema to 1.2. The rebase needs a careful three-way merge on the dispatch payload JSON.

Dispatch payload JSON and slot placeholders are SEPARATE surfaces

Easy miss: the orchestrator's per-claim dispatch payload (around paper-trail.md line 396) and the {{slot}} placeholders in the dispatch prompt are different files. Both need source_mode and paperclip_handle additions. Without the JSON-payload edit, the prompt slot has nothing to interpolate; without the slot edit, the prompt cannot consume the new fields.

pdf_ocr_fallback aligns Phase-2.5 and Phase-3 vocabulary

Today Phase 2.5 marks OCR-fallback entries with ingest_mode: ocr_fallback. Phase 3's source_mode enum uses pdf_ocr_fallback for the same condition — renaming under one vocabulary. The adjudicator's prompt weights this lower-confidence than plain pdf.

Open questions

Five questions the plan leaves open. Each has a default disposition recorded in the plan body — set status to Resolved, Deferred, or leave Pending as you review.

OQ1 — Repo concept (paperclip 0.3.0)

The new paperclip init <topic> / paperclip checkout <topic> workflow scopes subsequent queries to a "repo" of papers. Should one paper-trail run = one paperclip repo (auto-init at Phase 1, all Phase-3 queries scoped to it)? Pros: cleaner provenance, amortized work. Cons: extra setup; unclear interaction with --no-repo escape.

Plan default: Discover empirically — try both shapes in the smoke test.

Status:

OQ2 — Sibling co-citation: paperclip map or per-citekey loop?

Today the orchestrator dispatches one extractor-adjudicator chain per (claim, citekey) with multi-cite siblings in co_cite_context.sibling_citekeys. Paperclip's map primitive could fan out a single "does this paper support <claim>?" query across N siblings.

Plan default: per-citekey loop in v1 (parity with PDF mode); revisit map after smoke test.

Status:

OQ3 — Verifier: re-grep or LLM-based check?

Today's verifier picks an attestation line and re-checks the source. Paperclip's paperclip grep re-run is deterministic (same query → same hits), so the verifier becomes near-trivial. Should it stay deterministic, or keep an LLM-based judgment layer for nuance?

Plan default: deterministic re-grep in v1; LLM-based layer is a separate verifier-dispatch.md change orthogonal to this plan.

Status:

OQ4 — Authentication startup probe UX

Phase 0 should call paperclip config and check the Auth: ✓ line. If unauthed, the run goes to --paperclip=off. Open: one-line warning at start of run, or prompt the user to run paperclip login interactively?

Plan default: one-line warning plus auto-fall-back-to-PDF; user can re-run after login. Per memory feedback_author_mode_always_ask_path.md, no silent probes — the warning surfaces state.

Status:

OQ5 — abstracts source in Phase 1: opt-in or default?

Identity resolution via the abstracts corpus could surface wrong-paper citations the CrossRef chain misses. Cost is one extra paperclip query per Phase-1 reference (sub-second).

Plan default: default-on.

Status:

Out of scope

  • Parallel optimization. Per memory feedback_serial_then_parallel.md, harden the serial path first.
  • Replacing the PDF-centric path entirely. The external slice is permanent.
  • Citation hygiene checks beyond what the existing rubric does — this plan is a read-path change.
  • paperclip map as the dominant fan-out primitive — investigated in OQ2 but not committed in v1.
  • Author-mode-only or reader-mode-only behavior differences — symmetrical here; author-mode specifics belong in docs/plans/author-mode-parity.md.
  • Optimizing the paperclip skill prompt itself — refreshing from upstream is in scope; rewriting upstream's skill prose is not.

  2. Implement Phase 1 paperclip-aware verify-bib first. Run on Adamson refs.verified.bib. Expected: verified: 56/56 (paperclip:~27, external:~29, unresolved:0).
  3. Implement Phase 2 coverage-aware fetch-paper. Run on the same fixture with --paperclip=prefer. Expected: ~27 refs skip download; ~29 hit existing PDF-fetch path.
  4. Implement Phase 3 mode-aware dispatch. Run on a single claim (e.g., C001) in paperclip mode; evidence JSON validates against schema 1.2.
  5. Run end-to-end on the full Adamson fixture. Diff per-claim verdicts vs M1 baseline at examples/paper-trail-adamson-2025/data/claims/. Verdicts must agree on any reference where M1 produced a non-PENDING verdict.
  6. Run end-to-end on examples/DFD_authormode/ to confirm author-mode parity.

Success criteria:

  • Phase 1 hit rate matches May 1 probe within ±2 references.
  • No regression on per-claim verdicts vs M1 baseline.
  • Average per-claim wall-clock time on paperclip-mode references is materially lower than PDF-mode (no fetch, no GROBID).
  • Paywalled-reference handling at parity with today on the external slice.
