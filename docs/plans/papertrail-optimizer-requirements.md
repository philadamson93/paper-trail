1. **`program-v0`** — pin paper-trail's starting-point program (the dispatch-prompt bundle) that the engine plan's Phase 2c freezes and tags, resolving a branch-reconciliation problem first: the `sarol` branch's own prior optimizer design targets an older, now-superseded shape of the mainline pipeline.

**A2. Adjudicator variant — the crux decision (genuinely open, Phil's call, mirroring crc's A2).** Two candidates, both real, neither measured:

- **Mainline `adjudicator-dispatch.md`** (native `overall_verdict` enum). *For:* this is the actual, currently-maintained product — improving it is the real point, matching the engine plan's own "validate against real proven work" framing; it has continued to receive engineering investment (paperclip-first awareness) the frozen Sarol variant lacks. *Against:* no scorer exists for it against Sarol today — one has to be built (see below).
- **`experiments/sarol-2024/prompts/adjudicator-dispatch-sarol.md`** (Sarol's own 9-class rubric, emitted directly). *For:* a scorer (`parse_verdict.py`) and a 9-way→3-way collapse table already exist for it. *Against:* it predates `paperclip-first-architecture` and `repo-organization` — its prompt likely references stale paths and doesn't know about `source_mode`; it was never actually run to completion either, so "has a scorer" is not the same as "has a measured baseline"; and optimizing it would mean improving a rubric variant the shipped tool doesn't use.

**Prior art this recommendation builds on and must reconcile with.** `docs/plans/paper-tool-validation.md` (this repo, `main`) already drafted a native→Sarol-3-way collapse (`CONFIRMED→ACCURATE`; `OVERSTATED`/`UNSUPPORTED`/`CONTRADICTED`/`MISATTRIBUTED`→`NOT_ACCURATE`; `CITED_OUT_OF_CONTEXT`→`IRRELEVANT`; `AMBIGUOUS`→exclude), plus real, already-collected label-frequency statistics over **1,873 Sarol dev+test evidence annotations**, and named target baselines: **MultiVerS 0.59 micro / 0.52 macro F1** and **GPT-4 4-shot 0.65/0.45** (abstract-only variant, apples-to-apples with Sarol's own published setup). That draft predates four verdict values this repo's rubric has since grown (`OVERSTATED_MILD`, `OVERGENERAL`, `PARTIALLY_SUPPORTED`, `INDIRECT_SOURCE`) — the collapse below supersedes it for those values — but the frequency table and baselines are reusable today, no new run required, and anchor both the collapse's correctness check (Open Questions §2) and the "first real scoring run" success criterion (Verification), rather than inventing a fresh bar.

**Recommendation (not locked — flag for Phil, per the pattern crc's A2 followed):** freeze **mainline's current prompts** as `program-v0`, and **port the Sarol-rubric collapse logic forward as a Scorer-side mapping layer**, not as a competing adjudicator prompt. Concretely: build a **new** native `overall_verdict` → Sarol-3-way collapse — this operates on the **12-value `overall_verdict` field** (the 11 sub-claim verdicts plus the rollup-only `CONFIRMED_WITH_MINOR`), not `sub_claims[].verdict` directly, since Sarol labels per-claim (the mapping below is a first pass, not final):

```
overall_verdict                                 → Sarol 3-way
CONFIRMED, CONFIRMED_WITH_MINOR                 → ACCURATE
OVERSTATED_MILD, OVERSTATED, OVERGENERAL,
  PARTIALLY_SUPPORTED, UNSUPPORTED,
  CONTRADICTED, MISATTRIBUTED, INDIRECT_SOURCE   → NOT_ACCURATE
CITED_OUT_OF_CONTEXT                            → IRRELEVANT   (Sarol's own doc: "closest in Sarol is ETIQUETTE")
AMBIGUOUS                                       → excluded from the frontier denominator; reported as an abstention rate, not forced into a 3-way bucket
```

**Reachability defect + metric decision — OQ2 pass 1 RUN 2026-09-01, and the collapse did NOT pass cleanly.** The zero-cost cross-check against `paper-tool-validation.md`'s real gold distribution (1,873 dev+test evidence annotations; buckets verified to sum exactly: ACCURATE 1,463 / 78.1%, NOT_ACCURATE 376 / 20.1%, **IRRELEVANT 34 / 1.8%**) found the collapse above is **not injective against the gold labels**:

| Gold label | n | Sarol bucket | paper-trail verdict | Collapse sends it to | |
|---|---:|---|---|---|---|
| `INDIRECT` | 36 | NOT_ACCURATE | `INDIRECT_SOURCE` | NOT_ACCURATE | ok |
| `INDIRECT_NOT_REVIEW` | 17 | **IRRELEVANT** | `INDIRECT_SOURCE` | NOT_ACCURATE | **structurally unreachable** |
| `ETIQUETTE` | 16 | **IRRELEVANT** | `AMBIGUOUS` *or* `CITED_OUT_OF_CONTEXT` | excluded *or* IRRELEVANT | **ambiguous by construction** |

One paper-trail verdict (`INDIRECT_SOURCE`) covers two gold labels Sarol routes to *different* buckets, so 17 instances can never be predicted correctly by any program the optimizer can write, and a further 16 depend on which of two verdicts the adjudicator happens to emit. **Max achievable IRRELEVANT recall is ~50% before the model does anything.** (The plan's own frequency table foreshadowed this by labelling `INDIRECT_NOT_REVIEW` as "INDIRECT_SOURCE *(variant)*"; the collapse had no variant distinction. Note also that the table's "IRRELEVANT: 1" row is the *raw* label — the collapsed bucket is 34.)

**Why this is a metric problem, not a mapping problem.** Under a 3-class macro-F1, IRRELEVANT carries a full **one third** of the frontier scalar while being 1.8% of the data and half-unreachable; its F1 is capped near 0.67 with a perfect model and realistically lands far lower, dragging the headline 0.2–0.3 absolute for reasons no prompt edit can fix. Worse for the loop itself: **the optimizer would spend iterations chasing a ceiling it cannot reach by editing the program.**

**RESOLVED 2026-09-01 (Phil) — `primary_metric` = macro-F1 over the two REACHABLE classes; 3-way macro and micro both demoted to reported breakdown.** A first pass at this proposed 3-way micro-F1 and was **wrong** — recorded here because the reasoning is a trap worth not re-entering. For single-label multiclass, micro-P = micro-R = micro-F1 = accuracy, and ACCURATE is 78.1% of gold, so **a do-nothing program that always answers `CONFIRMED` scores micro-F1 0.781** — beating both published baselines (MultiVerS 0.59, GPT-4 0.65) while doing nothing. Worse, it is exactly the behaviour a citation-integrity tool must not have, and it would be the optimizer's cheapest winning move. (`paper-tool-validation.md`'s own class-imbalance note already made this argument. Note too that since 0.781 > 0.59, Sarol's published "micro" cannot be single-label accuracy over this distribution — it is presumably computed over the multi-label evidence structure — so micro is *not* the clean comparable axis either.)

The frontier scalar is therefore **abstention-adjusted macro-F1 over `{ACCURATE, NOT_ACCURATE}`**, the two classes the collapse can actually reach. This keeps macro's resistance to majority-class collapse (the do-nothing program scores **0.439** here, not 0.781) while removing the distortion of weighting a 1.8%, half-unreachable class at one third of the objective. **Reported in `breakdown`, never optimized:** full 3-way macro-F1 (the axis comparable to MultiVerS 0.52 / GPT-4 0.45, carrying the documented IRRELEVANT ceiling), 3-way micro-F1, per-class F1 for all three classes, the 3×3 confusion matrix, the abstention rate, and the misses-included variants. IRRELEVANT thus stays fully visible in the record without steering the loop. The rubric is **not** changed — splitting `INDIRECT_SOURCE` into review/non-review variants would make those 17 instances reachable and restore full 3-way macro as the natural objective, but it edits the just-frozen `program-v0` rubric and the shipped tool's enum for a 1.8% class, so it is the principled follow-up once a v0 curve exists, not now.

**Abstention caveat (re-pinned).** Sarol's published collapse has no abstention concept — every gold instance lands in one of the 3 buckets — so excluding `AMBIGUOUS` from the denominator makes any figure computed this way not directly comparable unless abstentions are also scored as misses. **Pin the naming:** `primary_metric` = `macro_f1_reachable` (abstention-adjusted, over ACCURATE + NOT_ACCURATE); `breakdown` carries `macro_f1_reachable_misses_included`, `macro_f1_3way`, `macro_f1_3way_misses_included`, `micro_f1`, `per_class_f1`, `confusion_matrix`, `abstention_rate`, and `irrelevant_reachability_ceiling`. No untitled second numbers.

**Implementation note.** This mapping is new code, not a migration of `parse_verdict.py`'s existing Sarol-9-class collapse (that collapse stays as-is for the Sarol-variant path, per Part D's reuse framing). Model it as a sibling script — e.g. `experiments/sarol-2024/scripts/collapse_native_to_sarol3.py` alongside `parse_verdict.py`/`stage_claim.py`/`record_usage.py` (proposed name, not locked) — factored so the dispatch shape (verdict-in, bucket-out) mirrors `parse_verdict.py`'s existing collapse function rather than diverging gratuitously.

This keeps the optimized program = the real, single, currently-shipping adjudicator (simpler `ProgramManifest`, one prompt not two candidate prompts), and makes the Sarol-specific work **adapter-owned scoring logic** — directly analogous to how the engine plan required crc's `event_f1_at_W` to be **net-new scorer code**, not a straight port of `05_score.py`. **This mapping is a proposal, not a resolution** — Phil should confirm it (or pick the Sarol-prompt-variant path instead) before Phase 2c's freeze; see Open Questions §1.

**C4. Engine-contract blockers Part C must handle (added 2026-09-01, from an independent compatibility audit against `agentic-label-opt` @ `6d621ac`).** These are consumer-side obligations unless marked otherwise. None of them block Part A or B.
