What this is for

Every number this experiment has produced so far came from a judging session that could read the entire repository — including the optimizer's own notes on where it had gone wrong, and a file carrying the answer key. Across 561 of those sessions nothing was actually read. But thirteen of them lost track of their task and fell back on looking around the working directory, and two listed the optimizer's own findings as things they might work on. The only thing standing between “listed” and “read” was that no human was there to say yes.

This plan makes the boundary a fact about the filesystem instead of a sentence in a prompt, and then proves it the way its absence should have been caught: plant a marker file where the answer key lives and show the program cannot open it.

Worth being clear about what it does not buy. It does not make the existing numbers wrong, and it does not by itself produce a clean baseline — the recut that a sibling plan is owed still has to be run, and it had to wait for this because 61% of one iteration's judging sessions read a stale verdict for the same claim.

The phases

Phase 0 — the integrity floor SHIPPED
  • Freeze the program so a run can say which bytes it scored. program-v0/manifest.json lists ten files, each hashed, reproducible from two source commits.
  • The engine dependency is pinned to a commit (optimizer/engine_pin.py), so the shared substrate cannot move underneath a run.
How we know it worked: freeze_program_v0.py --verify --tree program-v0 reproduces the hash 10/10; the materialization smoke rebuilds the tree byte-for-byte.
Phase 1 — the container boundary itself SHIPPEDchanged
What changed: The image-version check no longer compares against your laptop, on your ruling. The paragraph above it is superseded on that one point.
  • Every dispatch runs in a fresh container with exactly two directories mounted: the read-only snapshot of the program version being scored, and the staging root it writes evidence into.
  • One permitted network destination, named out loud rather than left implicit.
  • The credential is passed by name, so its value never appears in a command line or a run record.
  • A Runner that does not state its boundary cannot be built at all — there is no value meaning “no container”, because a baseline measured outside the box and iterations measured inside it are not a weaker comparison, they are an invalid one.
How we know it worked: 74 checks on the boundary's shape, including that granting the repo root is refused outright and that no part of the gold tree is mounted, descendants included.
Step 1g — the seal, proved rather than assumed SHIPPED
  • Sentinels are planted in a throwaway copy of every path the program must not read — the gold labels, the benchmark tree, the optimizer's own scores, and the answer key one hop below the release envelope. Never the real tree.
  • A live container cannot read one of them. The same probe paths read every one the moment the boundary comes off — so the result is not “a container that mounted nothing”.
  • The probed command line is asserted to be the one production renders, which is the difference between proving the fixture and proving the system.
How we know it worked: 31 checks against a live Docker daemon, in about two seconds.
Phase 2 — narrow what the program sees inside the box SHIPPEDnew
What changed: The whole re-scope note: which parts of this phase Phase 1 had already made true, and the two assumptions in it that turned out wrong.
  • Most of this was already true. The container's working directory already is the read-only snapshot of the version being scored, and the engine already refuses a grant that can reach the gold tree. Verified against the code and against a live container rather than rebuilt.
  • Genuinely owed and now built: a run refuses a program version whose frozen command file is missing, even though the repo itself ships one — it used to look in the repo and dispatch an incomplete freeze.
  • Command discovery is narrowed to the one location the manifest freezes. The old three-location search let a tree with a stale copy elsewhere pass as complete.
  • No dispatch writes a resumable session to disk.
  • One flag was rejected. --exclude-dynamic-system-prompt-sections moves the machine details into the first user message rather than removing them — a caching speed-up, not a containment control. Adopting it would have looked like a closed channel that was still open. A check now keeps it off.
How we know it worked: Probed in a live container: no .git, no CLAUDE.md in the working directory or any ancestor, none anywhere on the image, and no stored memory at all. Four gates, and eight deliberate breakages all caught.
Phase 3 — pin the configuration SHIPPEDnew
What changed: Built. Four deviations recorded, the biggest being that the plan's mount triple could not be pinned as written.
  • A run now refuses to spend unless the boundary it is about to use matches a hash committed in the manifest — checked on every grant, before a single claim is dispatched.
  • The hash covers the image by digest, the mounts by role, target and mode, the network policy and egress list, the tool surface and every option name, and the program's file list. The credential contributes its name only, so rotating a token is not a configuration change.
  • The pin is read from committed bytes. A plan-A gate once compared a sheet against a stub editable in the same tree, so one session rewriting both passed; a reference the same edit can move is not a reference.
  • The release stamp that read 'sarol-2024' on all ten payloads of the last run is gone. It carries the committed pin instead.
How we know it worked: Thirteen components each moved the hash when changed, one case per component; the worktree-edit attack is a live negative control against a throwaway git repo; twelve deliberate breakages all caught.
Phase 4 — reset the run state at run start SHIPPEDnew
What changed: Built. The existing run-scope gate was extended rather than duplicated, and iter/ added to what it resets.
  • Before anything is dispatched, the previous run's lessons sheet, per-iteration findings and releases are moved into a dated archive, and the tree is then asserted clean.
  • iter/ was the gap that mattered: releases are keyed by iteration number, not by run, so run two's iteration one silently overwrites run one's — and that file is exactly what the runner reads back at the end.
  • The runner archives and then asserts, rather than stopping to ask a human who is not there. Archiving is a move, never a delete, and the continuation override still skips it.
  • The assertion delegates to the existing gate rather than being a second copy of it, and a check proves the delegation by substitution.
How we know it worked: Nine checks including an archive round-trip, idempotence across two consecutive run ids, and the control the plan names: skip the archive and the assertion must fail. Seven deliberate breakages all caught.

Things that bit us

Do not fix a version mismatch by rebuilding the image to match your laptopnew
What changed: New gotcha, from the check going red overnight when the Mac auto-updated.

The check that the boxed program runs the same Claude Code as the Mac went red overnight when the Mac auto-updated. The laptop is the wrong reference: everything scored runs inside the image, and the laptop's CLI produces no reported number. Worse, the obvious repair — rebuild the image to match — swaps the instrument mid-experiment, which is what the check existed to prevent. It now asks whether the image contains the version its own label claims.

A crashed check suite is not a red check

Twice this week a deliberate break crashed the suite instead of turning a named check red, and a crashed suite prints nothing — so the one fact you needed is the one you cannot see. Both are fixed: the membership tests come first and short-circuit, and the suite refuses up front with an actionable message when its own boundary has drifted from its pin.

A check that cannot fail proves nothing

One gate asserted only that something was reported, and passed for the wrong reason when the branch it was meant to cover was disabled. It asserts the reason now. Only mutation testing finds this shape — reading does not.

Granting a subdirectory of a denied tree is the design, not a leak

The staging root the container writes to sits inside the optimizer's output root, which is denied. That is deliberate: the container sees the staged evidence and not the scores beside it. Gold and the benchmark tree carry a stricter rule with no such exception, and the two rules are asserted separately.

This repo and the shared engine both have a module called isolation

Any process needing both must save and restore the loaded modules, not just the search path. Restoring only the path leaves the engine bound under that name for the rest of the process. It cost a real bug, caught in review before it reached the dispatch.

The 2026-08-05 armed run's safety number is zero by construction

Container mode has no hooks, so nothing could have been denied. Never cite it as evidence the boundary held.

How the gap happened

Worth reading once, because the shape repeats. The requirement was not missing — it was written down in three separate documents, one of which says in so many words that a violation invalidates the verdict. None of it shipped. In the dispatching code, every one of the five controls that document specifies was simply absent.

It was traded away for something that worked. A step needed the session to find a settings file, so the reasoning was “keep a real checkout” — and “a real checkout” was quietly read as “the whole repository” in the very first commit, with no line in any plan recording the trade. A later document then claimed a stronger guarantee than its peers, on the grounds that there was nothing in the repo to deny access to. That was true of the gold labels and false of the file the loop writes back into the repo every iteration — which carries per-claim answers.

The lesson the plan draws, and the reason the verification here is what it is: a rule that lives only in prose is not enforced, and a guarantee nobody tried to break is not evidence.
