TL;DR

paper-trail becomes consumer #3 of the shared agentic-label-opt optimization engine (rad-eval #1, crc #2, MedVAL #4) — the first fully external one. The optimized program is pure Markdown: four dispatch prompts plus three contract files, with no code in the loop at all. It is scored against the Sarol 2024 citation-integrity benchmark.

Two decisions dominate the current shape. The program emits Sarol's own 9-class vocabulary rather than paper-trail's native 11-way enum, because bridging the two with a collapse left 17 gold instances structurally unpredictable. And the native taxonomy is being retired outright — git-trace showed it landed unsourced in a single commit three days before the repo's literature review, while Sarol's is human-annotated with reported κ. That retirement lands on main only after this optimizer work finishes.

Part A froze program-v0 self-verifyingly, and Part B is unblocked. Part C is no longer gated on a decision: Phil resolved OQ6–9 on 2026-09-01, which turned three open forks into sequenced work — split the rubric so the enum contract is genuinely immutable, re-freeze the manifest to 8 entries, then compose and tag one tree so the engine can materialize it. What stays open is OQ2's hand-sample pass and OQ5's fine-grained frontier question, neither of which blocks implementation.

Part A is now actually done, not just specified. The rubric is split, the manifest re-frozen to 8 entries (combined_hash 391f54fae7c5), and the composed tree tagged program-v0 — and the materialization smoke passes against the real engine: materialize() writes all 8 files from that single SHA, byte-faithful to the freeze. Part B and Part C are the open work.

Contracts — what is fixed and what the optimizer may edit

The output vocabulary is a fixed contract

The optimizer may edit everything that makes the rubric good — class definitions, boundaries, worked examples, tie-breaks, the worst-wins ordering, and all four dispatch prompts. It may not change the set of emittable labels, because the benchmark defines it and the Scorer consumes it.

As of OQ8 that line is physical, not just declared. Phil: "a contract file should be immutable." So the 9-class rubric splits in two — the enum names plus the 3-way collapse map move to an immutable verdict_enum_sarol.md, and the editable guidance stays in verdict_schema_sarol.md. The engine will not enforce this for you: contract_file=True is read in exactly two places (versioning.py:86-90, materialize.py:72-79) and both test presence, never content. Enforcement is consumer-side — the EDIT globset excludes every contract path, and the adapter re-hashes all three contract files against the manifest after each edit pass, failing the iteration rather than scoring a program that rewrote its own contract.

ACCURATE  OVERSIMPLIFY  NOT_SUBSTANTIATE  CONTRADICT  MISQUOTE
INDIRECT  INDIRECT_NOT_REVIEW  ETIQUETTE  IRRELEVANT

A label outside the enum is an ordinary invalid output — charged as a miss against its gold class and counted in error_class_counts. Never a crash, never silently re-bucketed. A bad edit simply scores worse and the loop rejects it, exactly as it handles every other bad edit.

⚠ The frontier scalar is 3-way MACRO-F1. Micro-F1 is a trap.

For single-label multiclass, micro-P = micro-R = micro-F1 = accuracy, and ACCURATE is 78.1% of gold — so a do-nothing program that always answers ACCURATE scores micro-F1 0.781, beating both published baselines (MultiVerS 0.59, GPT-4 0.65) while doing nothing, and rewarding precisely the behaviour a citation-integrity tool must not have. The same program scores macro-F1 0.292, which is the correct verdict on it. score_sarol3.py --selftest pins both numbers so this cannot be re-adopted silently.

Parts

Part A — Pin program-v0 Done, tagged + smoke green

A1/A2 fileset — the Sarol 9-class variant, resolved after one reversal. The mainline-plus-collapse alternative was rejected because the bridge is not injective: INDIRECT_SOURCE covers both INDIRECT (→ NOT_ACCURATE) and INDIRECT_NOT_REVIEW (→ IRRELEVANT), leaving 17 of IRRELEVANT's 34 gold instances structurally unpredictable and 16 more ambiguous — capping that class at ~50% recall while it carried a third of the macro-F1.

A4 closure — the fileset was not closed over its own spec_root references. Computed mechanically, not spot-checked: all members resolve; three referenced paths sit outside and are excluded with recorded reasons. OQ8 has since taken the fileset to 8 by splitting the enum contract out of the rubric, so the closure holds but the written manifest is owed a re-freeze. The Sarol variant's four stale .claude/ paths were repaired first, of which only one (:80, the output-schema pointer) was operational.

The paperclip hole — the real command reference loads at run time via paperclip skill, so it lives outside the freeze and two runs of one program version could diverge with no manifest diff. Closed by a version pin, enforced by a Runner preflight that returns infra_error before any claim dispatches.

Feedback on Part D

Gotchas — engine-contract blockers

The six Part C blockers, all consumer-side New
  1. Runner cost is neither accounted nor enforced, and the Runner is called three times per iteration, not twice — TRAIN, VAL, then a post-commit probe on VAL again. Calls 2 and 3 are redundant across iteration boundaries. B2's cost table counts TRAIN only, so it is short by a fixed 1,896 sessions per iteration. Adopt crc's consumer-side pattern; no engine change requested.
  2. No timeout exists anywhere in loop.py, and TRAIN/VAL status is never checked, with no try/except around those calls. A partial agentic failure scores as a quietly degraded metric or kills the run.
  3. _split is never injected despite the engine's own comment saying it is. The Scorer must stash it, or the ReleaseBuilder returns a train payload for the VAL call and hits LoopStop.
  4. PolicyConfig.repo_root must be pre-resolved or every read is denied. On macOS /tmp resolves to /private/tmp; the failure is silent and ends in a LoopPause the engine documents as "a calibration signal, not a failure."
  5. The materialized tree is not a runnable Claude Code project — .claude/* are git symlinks that materialize as regular files containing their target string, the orchestrator is deliberately excluded, and the tree is chmod'd read-only. Also: hook config is read from inside the materialized tree, so it will not exist unless it is a manifest entry. crc hit this independently.
  6. Call-shape asymmetry — Runner and Scorer are called positionally; ReleaseBuilder and the agent keyword-only. Uniform signatures in either style break one pair.

Verified good news: the audit chain is cross-process safe under nesting, and materialize/versioning are genuinely content-agnostic, so a pure-Markdown program is fine.

Two things that would need an engine change — deliberately not requested New

Cost-aware budget stops — superseded by crc's consumer-side pattern, which Phil resolved 2026-08-27 as explicitly NO engine edit.

An actor dimension on the audit ledger — paper-trail is the first consumer whose Runner also spawns hooked Claude Code sessions, and ledger rows carry no session or actor field, so a nested session's legitimate reads are indistinguishable from the optimizer's and would be judged against the optimizer's policy. Related: the final_eval tripwire scans the whole ledger rather than the current iteration, so one TEST unseal permanently poisons every later run reusing that file.

Feedback
The native taxonomy is being retired — provenance New

Traced through git rather than inferred from missing docs: the entire native enum — all 11 sub-claim verdicts plus CONFIRMED_WITH_MINOR — appeared fully formed in one commit (18b3832, 2026-04-19, the commit that first created the schema). No incremental derivation, no per-value history, no design doc. The repo's literature review is dated three days later and never discusses the taxonomy.

Sarol's 9 classes are human-annotated over 3,063 citation instances with reported Cohen's κ. Between an invented taxonomy and a validated one with ground truth, the validated one wins — and adopting it collapses the experiment/product fork entirely.

Caveat worth your attention

Provenance answers "was it derived?", not "is it load-bearing?" — and for one value the answer differs. AMBIGUOUS is not merely an enum member: it triggers Phase 4 "Ambiguity triage", an entire orchestrator phase, with interactive resolution. By the same line this plan already draws (workflow states stay, taxonomy goes), it arguably sits on the workflow side and was misclassified. Severity has no comparable machinery, so the provenance argument stands unmodified there. This does not affect the optimizer — only the deferred main adoption. Resolved 2026-09-01 (Phil, OQ7): AMBIGUOUS is kept as an orthogonal workflow flag outside the verdict enum — "triage is one thing in the orchestration work" — so Phase 4 survives while the scored label space stays the Sarol 9.
