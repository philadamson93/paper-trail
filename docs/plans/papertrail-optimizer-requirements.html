Gotchas

⚠️ sarol worktree lacks the src/ tree entirely

Confirmed by direct git inspection during review, not just plan prose: git ls-tree sarol -- src/prompts/ returns nothing; the same paths on main are populated (added by repo-organization, which also turned .claude/prompts etc. into symlinks pointing at src/). A fresh agent trying to open src/prompts/extractor-dispatch-paperclip.md on a naive sarol checkout will get a file-not-found. Part A3 now states the fix: freeze from main directly, never merge.

⚠️ "D42" decision-number collision in the source plan-of-record

experimental-plan-of-record.md reuses the label "D42" for two different decisions (the program.md-equivalent optimizer doc, and a separate "Autoresearch direct-lifts adopted" decision). Flagged in Part B as a pre-existing collision in the source doc, not this plan's error — whoever maintains that log should renumber, but it doesn't block this plan.

⚠️ Abstention (AMBIGUOUS) breaks direct baseline comparability

Sarol's own published 3-way collapse has no abstention concept. Excluding AMBIGUOUS makes the computed macro-F1 not directly comparable to MultiVerS/GPT-4 baselines unless abstentions are also scored as misses. Now pinned as two named fields: primary_metric (abstention-adjusted) and breakdown.macro_f1_misses_included.

⚠️ The new native collapse is not a migration of parse_verdict.py's Sarol-9-class logic

Easy to misread Part A2 as "reuse the existing Sarol collapse for mainline output." It doesn't — parse_verdict.py's 9-class collapse stays untouched for the Sarol-variant path; the recommended mainline path gets entirely new collapse code operating on the current 12-value overall_verdict.

⚠️ Cost/runtime risk is real and was previously unestimated

Each claim triggers 3 full nested Claude-Code subagent sessions; the ramp goes to 2,141 claims. Review added a Verification gate requiring a per-landmark $ estimate before any run beyond the single-claim smoke test — previously this was only prose ("needed before a real run"), not a gate.
